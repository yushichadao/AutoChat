# 体验审计报告

> 站在五种使用者的角度，把 AutoChat 从头到尾走一遍，记录**每一步会卡在哪**。
> 每条问题都标了处理结论：已修 / 待办 / 不做（并说明为什么）。
> 关联文档：[故障模式](FAILURE-MODES.md) · [逻辑与界面缺陷](LOGIC-UI-ISSUES.md) · [术语表](GLOSSARY.md)

---

## 零、定位与面向对象（先说结论）

**一句话定位**
AutoChat 是 **Windows 专属的「微信侧本地 AI 助手」**：注入 hook DLL 读写本机已登录的微信号，收到消息后按策略交给本地或云端的 OpenAI 兼容模型，再把回复发回微信。

**它不是什么**
- 不是「多平台机器人框架」：不连任何外部平台，不跨平台转发。
- 不是「装上就能用」的产品：它依赖注入第三方 DLL、锁定微信旧版本、管理员权限——**门槛在环境，不在模型**。
- 不是「群发工具」：护栏与法律边界是它的一部分，见 [LEGAL.md](../LEGAL.md)。

**面向对象（按优先级）**

| 优先 | 人 | 他要什么 | 现在的入口 |
| --- | --- | --- | --- |
| 1 | 会用电脑但不懂技术的普通用户 | 别让我看命令，让我点 | `autochat setup` / 图形化配置器 |
| 2 | 会 cmd 与 PowerShell 的人 | 能脚本化、能查状态、能自动化 | `autochat <命令>` + `--json` |
| 3 | 懂 TUI/CLI/GUI 的开发者 | 代码可读、模块边界清楚、零依赖 | `src/` 六层结构 |

**真正的产品门槛**（新人 90% 的挫败来自这里，而不是配模型）：
1. hook DLL 与**微信版本强绑定**，微信一更新就失效；
2. 注入需要**管理员权限**；
3. 需要**旧版微信**，而官方不提供旧版；
4. 「电脑上的号 == 手机上的号」，所以需要**小号**才能分辨谁在提问。

**三个入口的定位（收口后）**

| 入口 | 定位 | 适合谁 | 与其它入口的关系 |
| --- | --- | --- | --- |
| `autochat setup` | **唯一的初始化向导** | 所有人第一次用 | 与图形化配置器的向导卡共用同一状态机 |
| `autochat <命令>` | **命令行的完整能力** | 会脚本的人 | 与图形化配置器**平级**，能做的事一样多 |
| 图形化配置器 | **浏览器的完整能力** | 不想用命令行的人 | 同上 |

> 收口前的状态是「TUI + CLI + GUI 三套并行」，且 TUI 与 setup 逻辑漂移、GUI 与 CLI 能力不对等 —— 详见 [逻辑与界面缺陷 L11](LOGIC-UI-ISSUES.md)。

## 一、角色 A：完全不会使用电脑的人

> 「我只想让它在群里帮我答问题，安装什么的都行，但我不想碰命令行。」

| # | 卡点 | 严重度 | 处理 |
| --- | --- | --- | --- |
| A1 | 没有任何「双击就能跑」的东西：必须自己装 Node、敲命令 | 高 | 部分修：`tools/first-run.bat` 一键脚本；**未做**：真正的免安装包（涉及打包与许可，超出本轮范围） |
| A2 | 不知道从哪开始，README 近千行、20 多个目录 | 高 | 已修：README 重构为「这是什么 / 面向谁 / 三分钟上手 / 入口怎么选」；新增十分钟上手清单 |
| A3 | 「命令」太多，不知道敲哪一条 | 高 | 已修：`autochat help` 按「第一次用 / 运行 / 自动回复 / 模型 / 管理」分组；`setup` 是唯一向导 |
| A4 | 注入要管理员权限，却不知道怎么提权 | 高 | 已修：`autochat start --elevate` 自动弹 UAC |
| A5 | 关闭窗口后服务就没了，以为「坏了」 | 中 | 已修：`--background` 脱离终端；状态卡明确显示「运行中 / 没有在运行」 |
| A6 | 不知道机器人为什么不回 | 高 | 已修：体检按依赖顺序给出修复步骤；状态卡区分「未启用 / 已暂停 / 运行中」三种状态 |
| A7 | 找不到「暂停」这个按钮在哪 | 中 | 已修：暂停在状态卡与顶栏各有一处，且文案统一为「暂停自动回复」 |

**结论**：**这一类用户最大的问题不是「界面不够友好」，而是「没有一件能双击就用的东西」。**
本轮把向导、提权、状态可见性补齐了，但**真正的「双击即用」还没有**（需要打包分发，涉及许可与体积）。这是下一版最该做的事。

## 二、角色 B：只会电脑基本操作的人

> 「我会上网、看文档、点按钮，但不会敲命令。」

| # | 卡点 | 严重度 | 处理 |
| --- | --- | --- | --- |
| B1 | 图形化配置器一打开是 8 张平铺的卡片，没有主线，不知道先做哪步 | 高 | 已修：首启向导卡置顶（步骤条 + 当前步 + 一个动作按钮） |
| B2 | 界面里的两个勾选框文案几乎一样（「启用 AI 回复」/「硬总开关」），分不清 | 高 | 已修：合并成一个「自动回复开关」，放状态卡；旧项随配置废弃 |
| B3 | 会话表里是一排浏览器默认勾选框，没有说明，误点就关掉一个群 | 中 | 已修：换成自定义开关 + 「关掉后这个群完全不参与 · 立即生效」 |
| B4 | 枚举值显示英文（always / mention / never） | 中 | 已修：分段选择，显示中文（群里@我才回 / 群里都回 / 群里不回） |
| B5 | 想知道发生了什么，但没有日志视图 | 高 | 已修：服务日志卡（尾部 + 刷新 + 错误行标红） |
| B6 | 配了本地模型但 Ollama 没开，只看到「连接失败」 | 高 | 已修：模型服务卡可一键启动本地模型服务；向导在这种情况下直接给「启动 Ollama」按钮 |
| B7 | 每张卡不知道「下一步做什么」 | 中 | 已修：每张卡底部一条「下一步建议」 |
| B8 | 危险操作（卸载、清空上下文）一点就没 | 高 | 已修：动作按钮 + 二次确认框，写明后果 |
| B9 | 界面每 4 秒刷新，输入到一半被冲掉 | 中 | 已修：正在输入时不重绘 |

**结论**：界面最大的问题**不是丑，而是「信息平铺 + 同义重复」**——用户要在 8 张卡里自己拼出「现在到底缺什么」。向导卡 + 下一步建议条把这件事从用户手里拿走了。

## 三、角色 C：会用 cmd 与 PowerShell 的人

| # | 卡点 | 严重度 | 处理 |
| --- | --- | --- | --- |
| C1 | 体检有两套（`npm run check` / `npm run doctor`），结论可能不一致 | 高 | 已修：合并为一个；`tools/check-env.js` 变薄封装 |
| C2 | 卸载也有两套，且命令行那套**功能更弱**（不解除微信更新阻断、不支持 `--force/--dry-run`） | 高 | 已修：合并为一份实现，命令行与图形化配置器能力对齐 |
| C3 | 看不到日志，出事只能 `type data/autochat.out` | 高 | 已修：`autochat logs [--lines N] [--err]` |
| C4 | 没有版本命令，不知道自己跑的是哪版 | 中 | 已修：`autochat version` |
| C5 | 脚本化不了：输出都是给人看的，退出码一律 0 | 中 | 已修：多数命令支持 `--json`；退出码 0 / 1 / 2 |
| C6 | `autochat start` 是前台，关终端就没了 | 高 | 已修：`--background`（WMI 脱离终端） |
| C7 | 注入要管理员，只能自己右键「以管理员运行」 | 高 | 已修：`--elevate` 自动 UAC 提权 |
| C8 | 没有开机自启 | 中 | 已修：`autochat install --service` |
| C9 | 本地模型服务（Ollama）没开时，只会看到「连接失败」 | 中 | 已修：`autochat model service start/stop/status` |
| C10 | 输出重定向到文件里全是转义符 | 低 | 已修：颜色跟随 TTY，`--no-color` 可关 |
| C11 | 同一个命令在不同终端里表现不一样（PowerShell 执行策略） | 低 | 文档给出 PowerShell / cmd 两种写法 |

**结论**：命令行用户被伤害最深的地方是**「同一件事有多个入口，而且能力不一样」**——体检两套、卸载两套、向导两套。
本轮的核心改动就是把它们收敛成**一个能力一个入口**。

## 四、角色 D：懂 TUI / CLI / GUI 的资深开发者

| # | 卡点 | 严重度 | 处理 |
| --- | --- | --- | --- |
| D1 | 「图形化配置器只是同一套逻辑的另一种皮」——主次关系写进了代码注释与文档 | 高 | 已修：明确为**两个平级入口**，共享的是任务层；删掉「皮」的表述 |
| D2 | 同一份逻辑两处实现（config.json 读写、体检、卸载、向导），改一处忘另一处 | 高 | 已修：全部收敛到 `src/tasks/` 与 `src/core/` |
| D3 | 目录结构混乱：配置在 `src/config.js`、`.env` 读写在 `src/cli/env-file.js`、配置器服务端在 `src/setup/server.js` | 中 | 已修：六层重排（见 CHANGELOG） |
| D4 | 三大文件过大：`cli/index.js` 715 行、`setup/server.js` 641 行、`setup/ui/app.js` 39KB | 中 | 已修：拆成 `commands/*`、`api/*`、`cards/*`，单文件 ≤400 行 |
| D5 | 术语混乱：`MasterSwitch`/`总闸`/`硬总开关`/`启用 AI 回复` 指同一件事的不同叫法 | 中 | 已修：术语表 + 改名（`PauseState`、自动回复开关、暂停状态） |
| D6 | 界面用裸勾选框，前端没有控件规范 | 中 | 已修：控件库 + 测试强制 |
| D7 | 外部文本直接拼 `innerHTML`（群名可控） | 高 | 已修：统一转义 + 回归测试 |
| D8 | 静态资源路径穿越校验过弱 | 高 | 已修：`path.resolve` + 目录边界判断 |
| D9 | 接收路径改成三段式后测试没跟上，红灯被忽略 | 高 | 已修：假 hook 按 SQL 形态返回，补齐覆盖 |
| D10 | 文档声称「108 项全绿」，实际有 2 条红 | 高 | 已修：测试补齐；文档数字随实际更新 |
| D11 | 前端一个文件 39KB、无法局部维护 | 中 | 已修：拆成 `js/widgets.js` + `js/cards/*.js` + `js/main.js`（经典脚本 + 命名空间，避免 ES module 与令牌机制冲突） |
| D12 | 没有「一个能力一个入口」的纪律 | 中 | 已修：npm script 全部是 CLI 薄别名；`tools/*.js` 全部薄封装 |

**结论**：资深用户最在意**「改一处会不会漏改另一处」**。
本轮把「唯一事实来源」落到 `src/tasks/`，并用测试守住三条纪律：裸勾选框禁用、外部文本必须转义、退出码与 JSON 契约固定。

## 六、CLI ↔ 图形化配置器 ↔ npm 脚本：能力对照表

| 任务 | npm 脚本 | 命令行 | 图形化配置器 |
| --- | --- | --- | --- |
| 初始化 | `npm run setup` | `autochat setup` | 首启向导卡 |
| 环境体检 | `npm run doctor` | `autochat doctor` | 环境体检卡 |
| 启动服务 | `npm start` | `autochat start [--background] [--elevate]` | 状态卡「启动服务」 |
| 停止服务 | `npm run stop` | `autochat stop` | 状态卡「停止服务」 |
| 暂停自动回复 | `npm run pause` | `autochat pause [原因]` | 状态卡 / 顶栏 |
| 恢复自动回复 | `npm run resume` | `autochat resume` | 状态卡 / 顶栏 |
| 看状态 | `npm run status` | `autochat status [--json]` | 状态卡 |
| 看日志 | `npm run logs` | `autochat logs [--lines N] [--err]` | 服务日志卡 |
| 接模型 | — | `autochat model test / list` | 接一个模型卡 |
| 模型服务启停 | `npm run model-service` | `autochat model service start/stop/status` | 模型服务卡 |
| 锁定微信版本 | — | `autochat lock [--status]` | 安装与卸载卡 |
| 自动匹配 DLL | — | `autochat autodll [--write]` | 账号卡「自动检测」 |
| 按会话配置 | — | `autochat chats list/add/rm/enable/disable` | 按会话配置卡 |
| 上下文记忆 | — | `autochat context [id] [--clear]` | 上下文记忆卡 |
| 读写配置 | — | `autochat config get/set` | 各卡片的输入框 |
| 安装 / 卸载 | `npm run install` / `npm run uninstall` | `autochat install [...]` / `autochat uninstall [...]` | 安装与卸载卡 |
| 版本信息 | `npm run version` | `autochat version` | — |
| 演示链路 | `npm run demo` | `node tools/demo.js` | — |

**这张表就是「平级」的操作化定义：两边能力必须一一对应，多一项少一项都算没做完。**
